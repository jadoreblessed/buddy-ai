# Запись демо Buddy AI

Цель ролика: за 3–4 минуты показать путь одного синтетического стажёра от назначенного плана до доступа и связи с наставником. Все имена, заявки, сообщения и инструкции в этом показе тестовые.

## Подготовка на Windows

Открой PowerShell в корне своего клона репозитория и получи актуальный `main`:

```powershell
git status --short
git pull --ff-only origin main
```

Если есть несохранённые изменения или `pull` не проходит, не удаляй их: сначала разбери конфликт или используй отдельный свежий клон. Для чистой записи запусти отдельный проект Compose, не затрагивая текущие тестовые заявки:

```powershell
$env:BUDDY_WEB_PORT = '35174'
$env:BUDDY_MOCK_PORT = '38182'
docker compose -p buddy-video up --build -d
docker compose -p buddy-video ps
Invoke-RestMethod http://localhost:35174/api/plan
```

Открой `http://localhost:35174` и проверь, что появился план backend-разработчика. Команды запускаются из корня репозитория, где лежит `compose.yaml`. Перед вопросами к реальной модели укажи свой ключ и совместимые `AI_MODEL`/`AI_BASE_URL` в локальном `.env` по README, затем пересоздай API:

```powershell
docker compose -p buddy-video up -d --force-recreate api
```

Ключ в видео и переписке не показывай. До записи проверь один предметный вопрос «Какие доступы нужны?» в чате. Если модель недоступна или возвращает лимит, не снимай этот фрагмент: приветствие, ответ о наставнике и MCP-статус заявки работают без модели. Не называй эти детерминированные ответы генерацией модели.

Закрой лишние вкладки и уведомления, открой браузер на весь экран, поставь масштаб около 100–110%, убедись, что весь текст читабелен. Запиши 10 секунд пробного видео и проверь микрофон и изображение. На Windows можно запустить запись окна браузера `Win + Alt + R` через Xbox Game Bar, включить микрофон `Win + Alt + M` и той же комбинацией остановить запись. MP4 появится в «Видео/Captures». На Windows 11 также доступна запись выбранной области `Win + Shift + R` через «Ножницы»; проверь звук в пробном фрагменте.

## План кадра и речь

| Время | Действие на экране | Что сказать |
| --- | --- | --- |
| 0:00–0:25 | Главная: имя, позиция, текущий шаг, прогресс. | «Buddy AI помогает стажёру пройти первый день. План назначается по позиции из внешнего тестового сервиса, а прогресс обновляется по фактическому статусу заявки». |
| 0:25–0:55 | В плане нажми «Запросить доступ», покажи подтверждение, затем «Создать заявку». Перейди в «Моя заявка». | «Стажёр видит конкретное действие и подтверждает его. Заявка получает номер и ждёт согласования; сам шаг ещё не завершён». |
| 0:55–1:20 | «Спросить AI-buddy» → введи «статус моей заявки?» → покажи ответ и метку `MCP · статус заявки`. | «На вопрос о статусе Go вызывает один MCP-инструмент чтения заявки. Ответ соответствует назначенному плану; модель не создаёт и не согласовывает доступы». |
| 1:20–1:45 | «Моя заявка» → «Демо: согласовать заявку» → назад к плану, покажи выросший прогресс и следующий шаг. | «Согласование здесь имитируется. После него статус и прогресс пересчитываются, следующий шаг становится доступен». |
| 1:45–2:15 | В чате снова спроси статус. Если предметный вопрос прошёл предварительную проверку, задай «Какие доступы нужны?» и открой источник ответа. | «Повторный запрос показывает актуальный статус. Вопросы по адаптации помощник связывает с доступными тестовыми материалами и показывает источник». При отсутствии модели опусти второе предложение. |
| 2:15–2:45 | «Отгул на день» → выбери будущую дату → «Проверить заявку» → подтверди → покажи номер и ожидание. При желании согласуй демо-кнопкой. | «Есть и отдельный бытовой сценарий: заявка на один день с явным подтверждением и сохранённым статусом». |
| 2:45–3:25 | В чате спроси «Кто мой наставник?» → «Написать наставнику» → измени черновик → «Проверить сообщение» → «Отправить наставнику», покажи историю. | «Наставник берётся из того же назначенного плана. Сообщение отправляется в тестовый мессенджер, а интерфейс показывает результат и историю». |
| 3:25–3:40 | Вернись к плану или оставь на экране историю; спокойный финальный кадр. | «Это работающий прототип с внешним назначением плана, одним MCP-инструментом и несколькими сквозными сценариями. Для реальной эксплуатации нужны корпоративная авторизация и подключения». |

Если времени только две минуты, оставь план → заявка → MCP-статус → согласование → один ответ с источником (если модель работает). Отгул и сообщение наставнику покажи в отдельном длинном дубле.

## Перед сдачей

- Посмотри MP4 целиком: действия видны, голос слышен, фрагментов с ошибками и ключами нет.
- Убедись, что слова «MCP», «модель» и «демо-согласование» соответствуют реально показанным кадрам.
- Сохрани видео под понятным именем, например `buddy-ai-demo.mp4`. Для повторного чистого дубля можно остановить отдельный проект, удалить **только его** тестовый volume и запустить снова: `docker compose -p buddy-video down -v`, затем повторить команду запуска. Это удалит данные `buddy-video`.
