# Отчёт о покрытии

Измерено 2026-11-14 на Linux: Go 1.27.1, Node.js 24.21.0, npm 11.19.0, Python 3.12.3. Тестовые данные синтетические; обращения к платной или бесплатной модели не выполняются.

## Воспроизведение из корня репозитория

```bash
go test ./backend ./mock-service -coverprofile=coverage.out -count=1 -timeout=60s
cd frontend
npm ci
npm run test:coverage
npm run build
cd ..
python3 coverage_report.py coverage.out frontend/coverage/coverage-summary.json
```

`coverage.out` и `frontend/coverage/` игнорируются Git. Последняя команда завершается с ошибкой, если суммарное покрытие исполняемых строк не превышает 80%.

## Результат

| Код | Покрыто / исполняемых строк | Доля |
| --- | ---: | ---: |
| Go API (`backend`) | 486 / 541 | 89,8% |
| Go mock-сервис (`mock-service`) | 172 / 200 | 86,0% |
| React (`App.tsx`, `main.tsx`) | 140 / 147 | 95,2% |
| **Итого** | **798 / 888** | **89,9%** |

`backend/app.go`: 62 / 64, **96,9%** исполняемых строк (уже включено в backend). Файл `app_test.go` не имеет собственного процента: тесты исключены из покрытия, а его проверки покрывают `app.go` и другие файлы API.

Go штатно сообщает **88,2% операторов** по двум пакетам, а не процент строк. `coverage_report.py` переводит регионы Go coverprofile в непустые исполняемые строки исходников: строка считается покрытой, если исполнился хотя бы один покрывающий её регион; комментарии и строки только со скобками не учитываются. Для React используются строки из отчёта Vitest/V8 (`json-summary`). Это объединение двух инструментальных методик, а не утверждение, что `go test -cover` измеряет строки. В знаменатель включены все Go-файлы приложений, включая `main.go`, и оба авторских TSX-файла приложения; тесты, зависимости, сгенерированные файлы и CSS не включены. `main.tsx` остаётся без покрытия (одна исполняемая строка), но не исключён из отчёта.

Тесты проверяют назначение и смену плана, заявку и её согласование с ошибками и сохранением после перезапуска, роли демо-сценария, материалы и источники, ошибки модели через подставной HTTP-клиент, загрузку плана и повтор в React, чат и переходы к материалам. Покрытие не доказывает корректность произвольного ответа LLM и не заменяет проверку реальных прав пользователя.
