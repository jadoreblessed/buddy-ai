# Отчёт о покрытии

Текущий замер выполнен 2026-11-14 на Windows после добавления MCP: Node.js 25.2.1, npm 11.6.2, Python 3.14 (по выводу пользователя); версия Go не зафиксирована. Тестовые данные синтетические; обращения к платной или бесплатной модели не выполнялись. Предыдущий замер на Linux (Go 1.27.1, Node.js 24.21.0, npm 11.19.0, Python 3.12.3) дал 89,9% до добавления MCP.

## Воспроизведение из корня репозитория

```bash
go test -coverprofile=coverage.out -count=1 -timeout=60s ./backend ./mock-service
cd frontend
npm ci
npm run test:coverage
npm run build
cd ..
python3 coverage_report.py coverage.out frontend/coverage/coverage-summary.json
```

`coverage.out` и `frontend/coverage/` игнорируются Git. Последняя команда завершается с ошибкой, если суммарное покрытие исполняемых строк не превышает 80%.

## Результат

| Код | Покрыто / исполняемых строк | Доля |
| --- | ---: | ---: |
| Go API (`backend`) | 560 / 630 | 88,9% |
| Go mock-сервис (`mock-service`) | 231 / 283 | 81,6% |
| React (`App.tsx`, `main.tsx`) | 140 / 147 | 95,2% |
| **Итого** | **931 / 1060** | **87,8%** |

`backend/app.go`: 62 / 64, **96,9%** исполняемых строк (уже включено в backend). Файл `app_test.go` не имеет собственного процента: тесты исключены из покрытия, а его проверки покрывают `app.go` и другие файлы API.

В этом запуске Go сообщил **85,0% операторов** для backend и **80,5%** для mock-service, а не процент строк. `coverage_report.py` переводит регионы Go coverprofile в непустые исполняемые строки исходников: строка считается покрытой, если исполнился хотя бы один покрывающий её регион; комментарии и строки только со скобками не учитываются. Для React используются строки из отчёта Vitest/V8 (`json-summary`). Это объединение двух инструментальных методик, а не утверждение, что `go test -cover` измеряет строки. В знаменатель включены все Go-файлы приложений, включая `main.go`, и оба авторских TSX-файла приложения; тесты, зависимости, сгенерированные файлы и CSS не включены. `main.tsx` остаётся без покрытия (одна исполняемая строка), но не исключён из отчёта.

Тесты проверяют назначение и смену плана, заявку и её согласование с ошибками и сохранением после перезапуска, роли демо-сценария, материалы и источники, ошибки модели через подставной HTTP-клиент, загрузку плана и повтор в React, чат и переходы к материалам. Покрытие не доказывает корректность произвольного ответа LLM и не заменяет проверку реальных прав пользователя.
