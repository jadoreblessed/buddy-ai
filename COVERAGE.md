# Отчёт о покрытии

Текущий замер выполнен 2026-11-15 на Linux после добавления разговорного слоя, проверки цитат и MCP-статуса AI-buddy: Go 1.27.1, Node.js 24.21.0, npm 11.19.0, Python 3.12.3. Тестовые данные синтетические; обращения к модели во время покрытия не выполнялись. Предыдущий замер после разговорного слоя дал 88,4%; знаменатель вырос с изменением кода.

## Воспроизведение из корня репозитория

```bash
go test -coverprofile=coverage.out -count=1 -timeout=60s ./backend ./mock-service
cd frontend
npm ci
npm run test:coverage
npm run build
cd ..
python3 coverage_report.py coverage.out frontend/coverage/coverage-summary.json
```

`coverage.out` и `frontend/coverage/` игнорируются Git. Последняя команда завершается с ошибкой, если суммарное покрытие исполняемых строк не превышает 80%.

## Результат

| Код | Покрыто / исполняемых строк | Доля |
| --- | ---: | ---: |
| Go API (`backend`) | 905 / 1044 | 86,7% |
| Go mock-сервис (`mock-service`) | 352 / 414 | 85,0% |
| React (`App.tsx`, `main.tsx`) | 266 / 281 | 94,7% |
| **Итого** | **1523 / 1739** | **87,6%** |

`backend/app.go`: 62 / 64, **96,9%** исполняемых строк (уже включено в backend). Файл `app_test.go` не имеет собственного процента: тесты исключены из покрытия, а его проверки покрывают `app.go` и другие файлы API.

В этом запуске Go сообщил **85,9% операторов** для backend и **84,5%** для mock-service, а не процент строк. `coverage_report.py` переводит регионы Go coverprofile в непустые исполняемые строки исходников: строка считается покрытой, если исполнился хотя бы один покрывающий её регион; комментарии и строки только со скобками не учитываются. Для React используются строки из отчёта Vitest/V8 (`json-summary`). Это объединение двух инструментальных методик, а не утверждение, что `go test -cover` измеряет строки. В знаменатель включены все Go-файлы приложений, включая `main.go`, и оба авторских TSX-файла приложения; тесты, зависимости, сгенерированные файлы и CSS не включены. `main.tsx` остаётся без покрытия (одна исполняемая строка), но не исключён из отчёта.

Тесты проверяют назначение и смену плана, заявки на доступ и отгул с согласованием, ошибки и сохранение после перезапуска, отправку сообщения назначенному наставнику с изоляцией истории по плану, роли демо-сценариев, материалы и источники, приветствие и small talk без модели, отказ на офтопик, валидацию истории диалога, ошибки модели через подставной HTTP-клиент, React-загрузку и повторы, подтверждения перед изменяющими действиями, чат и переходы к материалам. Покрытие не доказывает корректность произвольного ответа LLM и не заменяет проверку реальных прав пользователя.
