# AI-buddy: тестовый сценарий ответов

## Цель и границы

Стажёр задаёт вопрос о назначенном плане, инструментах или доступах. Go получает актуальный план и статус заявки, выбирает относящиеся к вопросу синтетические материалы для назначенной позиции и передаёт их модели. На странице «Материалы» можно прочитать те же инструкции и текущий план. Модель **не** создаёт, не согласовывает и не меняет заявки или шаги. `X-Demo-User` — только имитация ролей, не корпоративная авторизация.

## Источники

- `backend/materials.json`: тестовые инструкции, темы, поисковые формулировки и область видимости позиций. Здесь же находятся восемь открытых ссылок со слайда 15 кейса (`url`), представленных в отдельном блоке страницы «Материалы». Ссылки не используются как инструкции или источники ответа модели; их содержимое не скачивается.
- `assigned-plan:<planId>`: актуальные роль, команда, назначенный наставник и канал, шаги, ресурсы и статусы из внешнего mock-плана, включая явное отсутствие заявки.

`GET /api/materials` отдаёт `{ "materials": [{ "id", "title", "content", "url?" }] }` для текущей позиции. Материал без `url` — демо-инструкция или назначенный план, с `url` — внешняя ссылка для самостоятельного чтения. Go выбирает для ответа только внутренние демо-материалы по темам вопроса; выдержки чата должны дословно входить в их видимое содержимое. Модель должна сослаться на ID выбранного источника, а Go отклоняет ответ с неизвестным ID или без ссылки. Эта проверка подтверждает происхождение выдержки и ссылки, **не** доказательство истинности всего текста модели. При неизвестной теме модель не вызывается. При несовместимых директивах материалов по одной теме Go показывает конфликт и предлагает уточнить у наставника, не выбирая инструкцию самостоятельно. Ни одна инструкция не выдаётся за регламент Авито.

## Поведение

1. `POST /api/buddy/answer` принимает JSON `{ "question": "...", "history": [{ "question", "answer" }] }`. Вопрос непустой до 500 символов; история необязательна, не более двух последних пар и до 700 символов в ответе. Некорректная история отклоняется до вызова модели.
2. Go получает текущий план стажёра; если источник недоступен, отвечает ошибкой, не выдуманным планом.
3. Подходящие источники выбираются по теме и назначенной позиции. Для вопроса о доступах ресурс берётся из текущего плана, а не из текста модели. Темы команды, первых дней, связи с наставником и обучения описаны отдельными синтетическими памятками и не выдаются за регламенты Авито.
4. Go вызывает Responses API с `store: false`, ограничением ответа и инструкцией отвечать только по выбранным материалам с ID источников. История диалога передаётся как контекст, а не как команда; короткое уточнение без собственной темы наследует тему последней пары. Интерфейс заменяет ID в тексте на кликабельную метку материала; она открывает полный текст в разделе «Материалы».
5. Приветствия, «как дела», благодарность, вопрос «кто ты» и «что ты умеешь» обрабатываются детерминированно без вызова модели: помощник представляется, кратко перечисляет темы и предлагает быстрые вопросы. Это работает и без API-ключа.
6. Просьбы написать код, решить учебную задачу или обсудить тему вне адаптации отклоняются детерминированно. Неизвестный вопрос без темы также получает отказ по области: помощник объясняет, что помогает с планом, доступами, материалами, отгулом и наставником, и предлагает безопасные варианты.
7. На точный вопрос о личности наставника Go возвращает детерминированный ответ по назначенному плану с `suggestedAction: "message_mentor"` и источником. Модель не выбирает получателя и не отправляет сообщение. Вопрос об отгуле может использовать только синтетическую инструкцию из каталога; оформление происходит отдельным API после подтверждения стажёра.
8. Если ключ не задан, лимит исчерпан или провайдер недоступен, для обычного AI-вопроса возвращается понятная ошибка; сценарный ответ не маскируется под ответ модели.

## Проверки

- Backend, frontend и analyst видят только относящиеся к их позиции инструкции и получают ресурс **своего** плана.
- При смене статуса заявки меняются актуальные шаги динамического материала; вопрос «что дальше?» учитывает текущий шаг.
- Приветствие, small talk и вопрос о возможностях не вызывают модель и предлагают быстрые темы; предметный вопрос в том же сообщении не перехватывается приветствием.
- Неизвестная тема и противоречащие директивы не вызывают модель и не порождают выдуманный регламент. Просьба написать код отклоняется даже при наличии слова «доступ».
- История диалога ограничена двумя парами, проверяется по длине и передаётся модели только как контекст; некорректная история не доходит до провайдера.
- Подставленный ID или отсутствующая ссылка модели не принимаются; выдержка должна встречаться в доступном материале.
- Пустой/слишком длинный вопрос отклоняется; ошибка провайдера не превращается в успешный ответ.
- Ключ остаётся только на Go-сервере; модель не получает инструментов изменения заявок.
- Вопрос о наставнике берёт его имя только из внешнего плана и не вызывает модель; предложенное действие не отправляет сообщение без подтверждения.
- Заявка требует отдельного подтверждения пользователя; одобрение доступно только демо-наставнику.

Детерминированные тесты проверяют выбор и происхождение данных через подставную модель. Отдельные пробы реальной модели нужны для качества формулировок: корректный доступ по каждой позиции, текущий/следующий шаг и отказ за пределами материалов. Проверка ID источника сама по себе не гарантирует, что модель не добавила неподтверждённое утверждение.
